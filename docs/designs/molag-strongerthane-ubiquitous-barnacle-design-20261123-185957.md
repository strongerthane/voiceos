## Problem Statement

VoiceOS is a full enterprise voice-assistant platform (analytics, workflows, smart plugins, search, scheduling, TTS, file organization) built for Windows, but it has zero paying users and no one using it without being asked. The product was built before validating demand — "platform vision before wedge." A rival holds ~80% market share in the space, but VoiceOS has no traction of its own. The team needs a landing/marketing webpage to explain what VoiceOS does, show its features, and drive a download CTA to the VoiceOS.exe installer.

## Demand Evidence

None. Pre-product stage — no paying users, no one using VoiceOS this week without being asked. Founder confirmed "None, but rival has some." Competitor traction is not VoiceOS traction.

## Status Quo

The clearest named user is the founder's dad: an investor managing 3 teams who handles email manually while doing investment work. When an email pops up he reads and responds, interrupting his primary task, and sometimes misses profitable margins. He currently pays a minimum of ~$16/month for something (unclear what). He has not yet been confirmed to have used VoiceOS.

## Target User & Narrowest Wedge

Target user: personal Windows users who want to operate their computer by voice with a compact, always-available assistant (PRODUCT.md positioning). Narrowest wedge for the landing page: a download CTA that drives actual VoiceOS.exe installs to personal Windows voice users, starting with the founder's dad as the first real target customer.

## Constraints

- Pre-product, zero paying users
- Competitor with ~80% market share (market exists, VoiceOS share unknown)
- Full enterprise platform already built but unvalidated
- $16/month price reference point
- Windows-only distributor: VoiceOS.exe built via PyInstaller (~180 MB, single-file GUI)
- macOS .app bundle and MSIX packaging are blocked (need Mac host / Windows App SDK respectively)

## Premises

All three agreed in Phase 3:

1. A landing/marketing webpage is the right next step for VoiceOS. — AGREED
2. There is a specific named target user (personal Windows voice users; founder's dad as first customer). — AGREED
3. A webpage download CTA drives actual VoiceOS.exe installs. — AGREED

## Approaches Considered

### Approach A: Single-page static site (minimal viable)

One HTML page covering hero, features, download CTA, and footer. Fewest files, smallest diff, ships fastest.
- Effort: S | Risk: Low
- Pros: fastest to ship, easiest to host on GitHub Pages/Netlify/Vercel, lowest maintenance
- Cons: limited room for feature depth and docs; all content competes for attention on one scroll
- Reuses: DESIGN.md gradient palette (cyan→magenta), PRODUCT.md feature list

### Approach B: Multi-page static site with design system (chosen)

Separate pages for Home, Features, Download, Docs sharing a CSS design-system token file (colors, typography, gradient, motion) derived from DESIGN.md and the app's floating UI.
- Effort: M | Risk: Low-Medium
- Pros: room for feature depth and a dedicated download page; design-system tokens keep the site consistent with the app's cyan→magenta palette and Segoe UI typography; pages can grow independently
- Cons: more files to maintain; needs a shared token file kept in sync with app design decisions
- Reuses: DESIGN.md visual system, PRODUCT.md features/capabilities, README feature list

### Approach C: Interactive voice demo landing page (creative/lateral)

A browser-based voice demo where visitors can try a voice command and hear TTS feedback before downloading.
- Effort: L | Risk: High
- Pros: dramatic proof of the voice-first value prop; memorable
- Cons: high build effort, browser mic permissions and STT/TTS costs, demo may not reflect the desktop .exe experience, distracts from the download CTA
- Reuses: voice pipeline concepts (voice_io.py, voice_feedback.py)

## Recommended Approach

Approach B: Multi-page static site with design system.

Rationale: The user explicitly chose Approach B after the premise challenge. It best matches the goal of a "fully functioning premium app" presence across app stores while keeping effort manageable. The shared design-system token file lets the site echo the app's translucent black notch, cyan→electric blue→violet→magenta gradient, and Segoe UI typography, so the landing page feels like the premium extension of VoiceOS rather than a generic marketing template. A dedicated Download page gives the CTA a clear home and a place to note Windows-first availability plus the blocked MSIX/Apple packaging as "coming soon."
